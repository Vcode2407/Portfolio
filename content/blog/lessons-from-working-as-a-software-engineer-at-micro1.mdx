Working remotely as a software engineer while pursuing M.Tech has pushed me to be sharper about ownership.

## Planning Is an Engineering Tool

Planning is not separate from implementation. Clarifying API behavior, data-model changes, edge cases, and validation steps before writing code makes reviews faster and reduces avoidable rework.

## Latency Hides in Coupling

Request paths become harder to reason about when unrelated work is tightly coupled. Separating responsibilities and making asynchronous boundaries explicit can improve both reliability and debuggability—but the design still needs clear delivery and failure semantics.

## Observability Changes Behavior

Better dashboards and deployment feedback make engineers more willing to ship small, reversible improvements. Observability is not a reporting layer after the fact; it changes how the team designs and releases software.
